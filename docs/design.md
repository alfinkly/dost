# dost: дизайн

Date: 2026-11-15. Status: approved design draft (written in Russian; an English version will follow). The project is early: nothing described here is implemented yet.

## Зачем

Работа с Ansible упирается не в сам Ansible, а в память человека: команд много, у них есть порядок, смысл каждой забывается, одни и те же ошибки возвращаются, а их решение уже забыто. И после запуска не видно простыми словами, что в мире изменилось.

`dost` — терминальный плеер для Ansible. Он:
1. показывает меню плейбуков с описанием «для чего» (без флагов и без запоминания путей);
2. запускает настоящий `ansible-playbook` и показывает происходящее живой сценой в консоли (порты закрываются, VPN-цепочка достраивается узел за узлом);
3. после завершения пишет человеческим языком, что теперь произошло («VPN wg1 развёрнут, SSH закрыт»);
4. при известной ошибке сразу показывает причину и решение;
5. помнит прогресс цепочек из нескольких плейбуков («осталось 3 из 6»).

Инструмент личный, открытый, в GitHub владельца. Им должен мочь воспользоваться кто угодно и быстро настроить под себя.

## Цели, не-цели, анти-цели

**Цели**
- Запуск без флагов: меню, подтверждение, `--check` перед применением.
- Красивая, понятная визуализация (стиль «фильмов про хакеров», но осмысленная).
- Каталог описаний лежит в проекте пользователя, а не в инструменте.
- Быстрый старт: `dost init` в каталоге с плейбуками даёт рабочее меню без правки руками.
- Один лёгкий бинарник на Rust без рантаймов.

**Не-цели**
- Не заменяет Ansible, не реализует свои модули, не хранит инвентарь.
- Не веб-сервис, не сервер, не раннер: работает только локально, у пользователя.
- Не система мониторинга и не платформа управления несколькими пользователями.
- Не Terraform и не любая другая IaC-система.

**Анти-цели (провал, даже если всё «работает»)**
- Визуализация, которая показывает неправду (картинка «зелёная», а на узле иначе).
- Пароль `sudo` или секреты в аргументах команды, истории, журнале или логах.
- Привязка к одной инфраструктуре: в коде или публичных примерах имена чужих узлов.
- Необходимость переписывать чужие плейбуки, чтобы вообще что-то запустить.

## Ограничения
- Платформы первой версии: macOS и Linux (решение автора, Windows и WSL позже).
- Язык: Rust (`ratatui`, `crossterm`, `tokio`); решение владельца.
- Лицензия: Apache-2.0; решение владельца.
- Запуск только локальный; никаких агентов на серверах и никаких серверных компонентов.
- Работает поверх обычного `ansible-playbook`; требует установленного Ansible.

## Подходы и выбор

Интерфейс: (A) shell + fzf, (B) Python TUI, (C) `ansible-navigator` + ARA. Выбран **Rust TUI** (решение владельца): один бинарник, быстрый отклик, хорошая работа с терминалом, удобно распространять открытым проектом. Shell-подход упирается в слабую логику состояния, `ansible-navigator` не даёт меню и итоговых сообщений.

Источник данных для сцен: (1) явные события из плейбуков, (2) разбор обычного вывода. Выбраны **явные события** (решение владельца). Разбор вывода остаётся только для общего прогресса и ошибок.

## Архитектура

```
 каталог проекта (пользователь)              dost (бинарник)
 .dost/                                      ┌───────────────────────────┐
   catalog/*.yml   ──────────────────────►   │ загрузчик каталога        │
   scenes/*.yml    ──────────────────────►   │ запуск ansible-playbook   │
   errors.yml      ──────────────────────►   │ поток событий (jsonl)     │
   state/ history/ (локально, не в git)      │ сцены и виджеты (ratatui) │
                                             │ итог, подсказки, история  │
 плейбуки пользователя ──события──────────►  └───────────────────────────┘
```

### Каталог команд (`.dost/catalog/<id>.yml`, по файлу на плейбук)

```yaml
id: perimeter
title: Периметр SSH
playbook: playbooks/node/perimeter.yml
about: Закрывает все порты, кроме нужных. Оставляет SSH только на порту 22.
danger: medium            # low | medium | high; для high нужно ввести id для подтверждения
needs_become: true
scene: ports
after:                    # порядок: что должно быть выполнено до
  - base
done: |
  Периметр развёрнут на {{ hosts | join(", ") }}.
  Теперь SSH доступен только по 22, остальные порты закрыты.
```

### Цепочки (`.dost/catalog/chains/<id>.yml`)

```yaml
id: preprod
title: Препрод
steps: [base, wg, perimeter, k3s, argocd, verify]
```

`dost` хранит локально, какие шаги цепочки выполнены и когда («3 из 6»). Это память инструмента, а не истина о серверах. Если плейбук изменился после запуска, шаг помечается устаревшим. Шаг `verify` (обычный плейбук-проверка, опционально) даёт настоящий признак «готово».

### Известные ошибки (`.dost/errors.yml`)

```yaml
- match: "Too many authentication failures|Connection reset"   # регулярка по тексту ошибки
  module: ansible.builtin.ping                                  # опционально
  cause: Провайдер ограничивает новые SSH-соединения.
  fix: Включи ControlMaster в ssh config, повтори запуск.
  link: docs/runbooks/ssh.md
```

При падении задачи плеер показывает совпавшие записи, затем общий итог.

### Контракт событий (v1)

Плейбук выдаёт событие обычной задачей, без плагинов и модулей:

```yaml
- name: report ports
  ansible.builtin.debug:
    msg:
      dost: { v: 1, kind: ports, state: { "22": on, "80": off, "443": on } }
```

`dost` запускает Ansible со своим встроенным callback-плагином `dost_stream` (он зашит в бинарник, пишется во временный каталог и включается через `ANSIBLE_CALLBACK_PLUGINS` и `ANSIBLE_STDOUT_CALLBACK`, так что коллекция `ansible.posix` не нужна). Плагин отдаёт `dost` поток JSON-строк с результатами задач, хостом, режимом запуска и сообщениями, у которых есть ключ `dost`. Хост берётся из потока, писать его в событие не нужно. Для авторов плейбуков по-прежнему не нужно ставить ни плагины, ни модули. Виды событий v1: `ports` (состояние портов), `link` (связь `a`—`b`: `up` или `down`), `node` (статус узла), `step` (название этапа, процент), `note` (текст). Неизвестные виды и версии игнорируются без ошибки. Вспомогательная роль `dost_emit` в репозитории инструмента даёт готовую задачу для копирования. Плейбуки без событий всё равно показывают общий прогресс, задачи и итог.

### Каталог визуализаций

- **Уровень 1, кирпичики:** `chain` (последовательность шагов со статусами), `table` (строки и столбцы с подсвеченными изменениями), `map` (узлы и связи на схеме), `graph` (произвольный граф зависимостей), `progress` (шаг N из M).
- **Уровень 2, сцены** — YAML-описания, которые собирают кирпичики и привязывают их поля к событиям:

```yaml
# .dost/scenes/ports.yml
id: ports
use: table
bind:
  rows: event.ports.state          # порт -> on/off
  columns: [было, стало]
  highlight: changed
animation: fade_off                # плавно гасит порты, которые стали off
```

Встроенные сцены первой версии: `chain` (общая цепочка шагов), `ports` («Периметр»: таблица портов было/стало), `vpn` («VPN»: карта узлов, связи достраиваются по событиям `link`; узел, который не встал, виден обрывом цепи), `config` («Конфигурирование»: список изменённых файлов и сервисов по результатам задач). Пользователь может определить свою сцену из кирпичиков и поменять тему цветов (`.dost/theme.yml`).

### Запуск и безопасность
- `ansible-playbook` запускается как дочерний процесс. `dost` не выполняет ничего на серверах сам.
- Сначала `--check --diff`; применение только после подтверждения в интерфейсе. Для `danger: high` нужно набрать `id`.
- Пароль `sudo` (`needs_become`) вводится в отдельном поле и не попадает в аргументы процесса, в файл на диске постоянно, в историю, журнал и сохранённый вывод. Способ передачи Ansible выбирает строитель (требования выше).
- Сырой вывод запуска сохраняется в `.dost/history/` (в `.gitignore`), с вычищением значений, помеченных `no_log`.

### Команды
`dost` (меню по умолчанию), `dost run <id>`, `dost chain <id>`, `dost status <chain>`, `dost history`, `dost init`, `dost demo`, `dost doctor` (проверка Ansible, `jsonl`-callback, прав каталога). Основной режим — меню; подкоманды нужны для скриптов и обучения.

### Быстрый старт для чужого пользователя
1. `dost init` в каталоге с плейбуками: сканирует `playbooks/`, создаёт заготовки каталога (название по имени файла, `about` пустое, сцена по умолчанию `chain`).
2. `dost` — работающее меню сразу.
3. `dost demo` — демонстрация сцен на встроенных плейбуках с `localhost`, серверы не нужны.

## Объём версии 0.1
Меню; запуск с `--check` и подтверждением; ввод `become`-пароля; поток jsonl и общий прогресс; цепочки с состоянием; итоговое сообщение `done`; известные ошибки; сцены `chain`, `ports`, `vpn`, `config`; `init`, `demo`, `doctor`, `history`; тесты отрисовки на тестовом бэкенде `ratatui`; README на английском и лицензия.

## Что остаётся строителю
Структура модулей Rust, выбор крейтов для YAML и регулярных выражений, формат файла состояния, детали анимации и палитры, способ передачи `become`-пароля Ansible при выполненных требованиях безопасности, формат вывода `dost doctor`, текст справки. Отдельно: сверить встроенный callback `dost_stream` с актуальными версиями ansible-core и проверить передачу пароля через `/dev/fd` на macOS и Linux.

## Уточнения после проверки строителем (решения автора, на подтверждение владельцем)

1. **Событие из `--check` не должно выглядеть как факт.** `dost` знает, в каком режиме запустил Ansible, и помечает поток: в режиме проверки сцена рисуется приглушённо с подписью «ПРОВЕРКА, предварительно», окончательное состояние показывает только реальный прогон. События с одним ключом внутри `loop` перезаписывают друг друга, последнее побеждает. Задачи с `no_log` события не отдают; на задачу-событие `no_log` ставить нельзя, `dost doctor` предупреждает.
2. **Пароль `become`:** основной способ — анонимный канал и `--become-password-file /dev/fd/N` (Ansible читает файл один раз при старте, пароль нигде не лежит на диске и не виден в аргументах). Запасной способ, если на какой-то платформе не заработает, — управляющий pty для запроса `BECOME password:`, а stdout Ansible при этом идёт отдельной трубой. Оба варианта строитель проверяет на macOS и Linux.
3. **Один `become`-пароль на запуск**, одинаковый для всех хостов. Пароли ssh и vault в 0.1 не запрашиваются: ssh по ключам, vault только через `vault_password_file` из `ansible.cfg` проекта (`dost` ничего не перехватывает). Если Ansible спросит интерактивно, запуск завершается ошибкой с понятным сообщением, `doctor` об этом предупреждает.
4. **«Устаревший шаг»:** хэш файла плейбука плюс необязательный список `watch: [globs]` в каталоге (роли, vars); `dost init` заполняет `watch` простым поиском ролей. В интерфейсе формулировка «мог устареть», а не «устарел»: это память инструмента, а не истина.
5. **Параметры запуска:** поля каталога `inventory`, `limit`, `tags`, `extra_vars`; по умолчанию берётся всё из `ansible.cfg` проекта. Корень проекта — каталог с `.dost/`, `ansible-playbook` запускается из него. Перед подтверждением показывается точная командная строка (без секретов).
6. **Шаблон `done`:** крейт `minijinja` (совместим с Jinja, лёгкий). Контекст: `hosts`, `stats` (ok, changed, failed по хостам), `events` (по видам и хостам, например `events.ports.<host>.state`), `results` (результаты задач).
7. **Падение `--check`:** запуск применения блокируется, показываются ошибка и подсказка из `errors.yml`; пропуск проверки возможен только с явным подтверждением (для `danger: medium` и выше нужно набрать `id`). Поле каталога `check: false` отключает проверку для плейбука, который в check-режиме ломается, с видимым предупреждением «без проверки».
8. **Сцена `config`** берёт данные не из событий, а из результатов задач (`changed`, имя задачи, `diff`, если он есть). Это исключение из принципа «явные события»: встроенные сцены могут использовать `results`, если им не нужны данные, которых нет в стандартных результатах. Если `diff` недоступен, показываются только названия.
9. **Свой callback вместо `ansible.posix.jsonl`:** см. выше; зависимость от коллекции убрана. `dost doctor` проверяет, что плагин загружается.
10. **Привязка `bind`:** простые точечные пути с `[*]` для списков, без полного JSONPath. Сцены проверяются при загрузке, `dost doctor` показывает ошибки привязки. Короткая грамматика входит в документацию.
11. **Много хостов:** события ключуются по (хост, вид, ключ). События с тем же ключом перезаписываются, с разными накапливаются. Для `vpn` на N узлов сцена масштабируется; если не помещается в терминал, показывается список.
12. **Версии и терминал:** ansible-core 2.15 и новее, актуальная стабильная версия Rust, терминал от 80×24; truecolor используется при поддержке, иначе 256 или 16 цветов. Без tty (канал, CI) TUI не запускается, выводится обычный лог шагов и итог.

## Реализовано иначе, чем описано выше (версия 0.1)

Описание фактического поведения на английском: [design.en.md](design.en.md). Отличия от текста выше:

- Событие `link` несёт поля `a`, `b`, `state` в данных (ключ не разбирается, потому что в именах узлов бывают дефисы).
- Событие `ports` может нести `was` рядом с `state`; без него колонка «было» показывает «—».
- Привязки сцен (`bind`) вычисляются отдельно для каждого хоста по контексту `{host, event: {вид: данные}}`.
- Виды сцен: `chain`, `table`, `map`, `results`; поле `animation` принимается, но в 0.1 не отображается.
- Режим запуска передаётся callback-плагину переменной `DOST_MODE`.
- Подтверждение с набором `id` происходит после успешной проверки; после неудачной проверки применить можно только клавишей `a` и набором `id`.
- Цепочка запускается по одному шагу: `dost chain <id>` открывает следующий невыполненный или «мог устареть» шаг.
- Без терминала `dost run <id>` запускает только проверку; применение требует `--apply`, для `danger: high` ещё `--confirm <id>`; sudo-пароль читается из первой строки stdin.
- Интерфейс англоязычный (кроме метки «ПРОВЕРКА, предварительно»); локализация вне объёма 0.1.
